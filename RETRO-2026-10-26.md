## 3. `HEATHCOTE-PAGES` is the eighth named instance of the exact same mispricing shape, with a gate already in place

`HEATHCOTE-PAGES` ran 3.49x its USD 5 cap because "the two subagent calls that transcribed the Barwick Tabula
Cryptographica (684 rows over two dense leaves) ran long, the GOLD-4D shape." Its own lesson text names the
fix: "a dense printed table is a transcription unit priced per ~50 rows..., never a page look." This is
exactly the shape CLAUDE.md's Usage section has documented, by name, seven times before this one (GOLD-4D,
AT55V, MEYE, GOLD-K2, AX-COMP2, AX-4612TR, bMALS) — and `tools/brief_price_check.py` (built 16 Oct 2026,
specifically for the vision-call-counted-unit rule) was already running. I read the tool: it correctly checks
that a brief's own `vision calls: N x USD r = X` line is internally consistent and within cap, but it has no
way to know whether N itself is right for the actual source — a brief that calls a 684-row double-leaf table
"8 page looks" passes the gate cleanly, because the gate only re-checks the arithmetic of the number given,
never the size of the thing being priced. The gate closed the hole RETRO-2026-10-03-acct3 P2 and
RETRO-2026-09-28 P4 found; this is a different hole in the same wall.

## 6. Proposed changes (five; applied by nobody in this run)

**P1. `tools/brief_price_check.py`: a dense/table source must state its row count, and N is derived from it.**
Motivating row: `HEATHCOTE-PAGES` (section 3), the eighth named instance of this exact shape.
```diff
+# A brief describing a source as a "table", "register" or "dense leaf" (not a plain page) must also state an
+# estimated row or entry count; the gate then requires vision calls >= ceil(rows / 50) for that unit (the
+# ~50-rows-per-call rate HEATHCOTE-PAGES's own lesson names), not merely a self-consistent N x r = X line.
+TABLE_RE = re.compile(r'\btable\b|\bregister\b|\bdense (?:leaf|page)\b|\btabula\b', re.I)
+ROWS_RE = re.compile(r'(\d+)\s*rows?\b', re.I)
```
A brief naming a table with no row estimate fails the same way a missing vision-calls line already does; one
with a row estimate but too few calls fails with the expected count printed.

**P2. Report over-cap rows split by severity, not as one blended rate.**
Motivating evidence: section 2 (8 of 12 D- rows under 1.3x, 4 real).
```diff
+# tools/ledger_check.py --over-cap-severity FROM_ROW: for D- rows with a parsed "Nx cap" ratio, print counts
+# and rows for ratio < 1.3 ("near-cap, likely noise at small dollar caps") vs >= 1.3 ("real miss, worth a
+# lesson"), so a retrospective reports both numbers instead of one blended percentage.
```

**P3. Price a page-build or browser-fetch job per actual unit, following the workers' own named fixes.**
Motivating rows: `SORTER-KING` ("have the worker render with tools/sign_sorter.py without reading the
template"), `HEATHCOTE-HOLDER` ("price each browser fetch as a unit... about USD 0.7 each").
```diff
+README common tail: a sorter-build job renders through `tools/sign_sorter.py` directly; a worker that reads
+the page template into its own context to build it is pricing the template's size, not the job.
+A browser-fetch step on a client-rendered catalogue prices each fetch at ~USD 0.7, the same way a vision
+call is a counted unit (Usage 6) -- a curl-shaped price on a browser-shaped step undercounts it.
```
