## Proposal 2: generalize CLAUDE.md rule 3's control-design lesson to cover control-*normalization*, not only
control-*design*

Rule 3 already carries the Salviati lesson (a control at the right N and K but the wrong design has no
evidentiary value). PX-BRODEC's gate (LEDGER.md:608, ROOM.md 09:18-09:19) was the right design (leave-one-out
over the same appendix) but compared two transcriptions written to different conventions — the decode spells
words out, the period gloss it was diffed against abbreviates them — so the metric measured a convention
mismatch, not a decode error, and returned a false 50-68% instead of an unmeasured (but probably much higher)
real agreement.

```diff
--- a/CLAUDE.md
+++ b/CLAUDE.md
@@ rule 3
 control that already solves blind has no headroom to show a gain regardless of the technique. Lesson of 24 Sept 2026
 (solvEX): the brief gated the Salviati target's run on a control at "N=720, K=36 (Salviati's own N and K)"
 but used a simple-substitution design at that N, which reads 99.7% blind on 3 seeds -- already on file before
 the brief was written. Salviati's own cipher is code+mark (cm), which at the same N reads 22-67% blind (LANE
 R4 P's curve): match the *design*, not only the length and symbol count, when the question is whether a
 technique adds anything.
+   A matched design is not enough if the two texts being diffed use different transcription conventions.
+   Lesson of 25 Sept 2026 (PX-BRODEC): a leave-one-out control diffed a fresh body decode against the
+   appendix's own period gloss and returned 50-68% against an 80% gate, apparently a failure -- but the gloss
+   abbreviates ("S.d±" for "Snr D.") while the decode spells the word out, so most of the gap was notation, not
+   error. Before diffing two renderings of the same underlying text for a gate, normalize both to one
+   convention (expand abbreviations, one case, one punctuation set) or the gate measures whichever side
+   transcribes more literally, not correctness.
```

Motivating rows: LEDGER.md:608 (PX-BRODEC, N); ROOM.md 09:18-09:19 (PX orchestrator's own postmortem, already
correctly diagnosed — this proposal only moves the lesson to where the next brief-writer will read it before
making the same mistake, the way the Salviati lesson already does).

## Proposal 5: report cost-per-counted-solve by lane at every parent check-in, not only at retrospectives

per-lane liveness ("PX live," "rate allowed") but never divide a lane's running spend by its solve count, so

from LEDGER.md after the fact. Given four of eight lanes closed zero solves for $240 combined this window
(54% of spend) while three lanes closed one each for $191.50 combined, the parent — who is the one actor
deciding whether to keep a lane open, redirect it, or accept another successor-chain (RD03→RD03B→RD04-style) —
would see this shape in real time rather than at the next retrospective if the number were in the check-in
line.

```diff
--- a/STATUS.md
+++ b/STATUS.md
@@ Parent handoff section, check-in line format
-Check-in <time> UTC: <lane status prose>. Board: <N> entries at N3+ (<letters>), <M> with our own key. Rate limit allowed on every lane.
+Check-in <time> UTC: <lane status prose>. Board: <N> entries at N3+ (<letters>), <M> with our own key. Cost/solve
+today by lane (lane cost so far / counted solves today, "n/a" if zero): <LANE: $X/N, ...>. Rate limit allowed on
+every lane.
```

Motivating rows: the lane totals in the "Cost per counted solve" table above, drawn from LEDGER.md rows
528-609; STATUS.md lines 105-121 (the existing check-in format, which has no cost field at all despite
