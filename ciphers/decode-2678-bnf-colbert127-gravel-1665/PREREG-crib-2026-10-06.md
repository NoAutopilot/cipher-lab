# Pre-registration: crib test of the enciphered recipients (R8-G2678, 6 Oct 2026, written 04:08 UTC before any candidate was tried)

Cipher material (passA.tsv, re-confirmed on canvas 356 at native resolution 6 Oct 2026):
- `29` -> 15000 Reichsdaler (one group; a code number, not spelled)
- `80 62 41 73 3̄2 51` -> 500
- `Mr Frichmann` in clear -> 600
- `4̄8 93 71 37 6̄0 92 580` -> 1000 "pour la demye année de leur pension" (plural "doivent": two or more people)

Arithmetic check: 15000 + 500 + 600 + 1000 = 17100 = the bill of exchange named in line 3 ("dixsept mille cent").
The reading of every amount, including "600" (passA flagged "or 60"), is therefore confirmed.

Planned test: fix a candidate list of 1664-65 Regensburg/Rhine-League pensioners from a printed source, then ask
whether each candidate name (or name pair) is consistent with the groups under a letter/syllable substitution,
against a control list of unrelated names of the same lengths.

Gate check before running (CLAUDE.md rule 3, "a control that cannot vary on the same axis ... licenses nothing"):
the 12 groups of the two spelled names are all distinct (80 62 41 73 32 51 48 93 71 37 60 92; 580 is a 3-digit
group, distinct too). With no group repeated, *every* candidate string of compatible length is consistent with
some homophonic letter or syllable key, and so is every control string. The consistency statistic cannot differ
between target candidates and the control by construction. Verdict, registered here: **the crib test is a non-test
at this N and is not run.** Nothing is ranked and no candidate is reported as fitting.

What would make a crib test able to fail: (a) a second text in the same key (another Guibert/Gravel letter of
1664-65 with a group repeated across names), or (b) a stated key design that orders the numbers (e.g. an
alphabetical table where values rise with the letter), which turns length-only consistency into a rank test --
neither is in hand; (b) is a design hypothesis no source here supports yet.
