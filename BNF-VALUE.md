## 1. The dataset (BNF-VALUE.tsv)

`BNF-VALUE.tsv`, regenerated by `python3 tools/holder_dataset.py --holder bnf --out BNF-VALUE.tsv` (`--check` fails
when stale). One `folder` row per target folder whose shelfmark is a BnF fonds, one `reading` row per verifier-classified
reading (status.json `results` with a `document_id`). Columns: row_kind, folder, shelfmark, item, status, n_class, depth,
depth_pct, key_source, text_known, gallica_ark, audit, title, repo_path.

| by status | found-solved 30, blocked 25, partial 25, open 15, closed-negative 6, solved 2, key-only 1 |
| folders with a verifier AUDIT.md | 24 |
| classified readings (item rows) | 33: N0 14, N1 1, N3 9, N4 9; depth D0 2, D1 16, D2 12, D3 1 |
| of which N3 or better | 18 (7 at D2 or deeper) |
| key source of the readings | published 21, period 9, ours 3 |

What a library can take from it, per item: the shelfmark and folio, the Gallica ark, whether the cipher is already
read on the leaf or in print (`found-solved`, N0/N1), whether this project read it with a published or period key
(N3/N4, with depth), and which items were tested and failed with a matched control (`closed-negative`).
Gaps in the dataset as built: the `gallica_ark` column holds the volume ark, not the leaf view (`/fN`); canvas
numbers are in each folder's NOTES.md and differ from folios, so leaf links are a follow-up (one line per reading,
from the folder's own canvas notes). `found-solved` folders often record *who* read the item first (Tomokiyo,
Bourdeau, DECODE, a period clerk); that column is not yet extracted.
