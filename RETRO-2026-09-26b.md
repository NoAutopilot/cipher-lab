## 5. Two different targets this window used a control that cannot fail differently from the target by

"identical by construction" -- its own NOTES.md correctly names this as the job brief's error, not the worker's:

token order at all, so shuffling order can never move it). `AX-5799` (00:36, D-) built a "value-shuffled" control
for a run-length gate meant to test whether numeral runs land on keyed positions, but the shuffled-*value* control
cannot change *which positions* carry a run of length >=10 -- the gate measured position structure, and the
control varied something else entirely, so "0% both, identical" told the worker nothing; its own lesson line says
so directly ("a key-reuse control must be able to fail differently from the target; a coverage-only gate is not
one"). Both are the same root failure as rule 3's headline paragraph (a control must be able to fail, on the same
axis as what is being measured) but neither the headline paragraph nor any dated lesson under it names this
specific shape -- a control invariant, by construction, under exactly the manipulation the family_run/gate design
is supposed to vary -- and it occurred twice in one window, independently, in two different lanes. Worth a rule 3
paragraph so the next job brief's own control choice is checked against "can this control's number ever differ
from the target's, for this exact statistic" before it is run, rather than discovered as a null result after the
fact.
