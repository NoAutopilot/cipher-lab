## 2. A brief specifying a summed scoring objective did not name the objective's own degenerate optimum, and the
   control caught it -- but only after a tool was built and both controls were run

AX2-4612S's brief (`.claude/briefs/runs/2026-09-26-lane-ax2-4612s.md`) told the worker to build `key_repair.py`
scoring each candidate code value "by the fr16 order-5 model's **total** log-probability of the whole decoded
stream" -- a sum, not a mean, over a variable-length output. Every character contributes a negative log-probability,
so deleting a code to NULL (shortening the stream) can only raise this total score, whatever the deleted code's true
value was. The worker built the tool exactly as specified (10-check offline test, `--help`, deterministic) and its
own null control caught the flaw immediately (100 of 110 synthetic single-code corruptions "repaired" by deletion,
gate <=2) -- so the control did its job and no target was run on a broken tool (AX2-4612S, LEDGER.md: "the brief's
error, not the worker's... a score summed over a variable-length output must be length-neutral before it can judge
a deletion"). This is exactly what a control is for, and it worked; the miss was earlier, at brief-writing time --
nothing in `.claude/briefs/runs/` or `.claude/briefs/README.md` asks a brief author to check a stated scoring
objective for a free lunch (a trivial or degenerate output that scores well without being right) before a worker
spends a build-and-control cycle finding it the hard way. This is a first occurrence (Usage 8a's "broken twice"
threshold is for a *tool*, not a template line), but the fix is one sentence, cheap enough to add without waiting
for a second incident, and precisely targeted at what actually went wrong (an unstated failure mode, not a bug in
the worker's code).

```diff
--- a/.claude/briefs/README.md
+++ b/.claude/briefs/README.md
@@ (new bullet, after the "Orphan check" bullet, end of file)
+- **Name the objective's degenerate optimum (26 Sept 2026, AX2-4612S).** A brief that specifies a scoring function
+  for a worker to optimize (log-probability, coverage, edit distance, any score summed or maximized over a
+  variable-length or variable-count output) names, in the same sentence, what trivial or degenerate output would
+  score best under it -- an empty string, every code deleted, every slot set to the same value -- so the worker
+  either rules it out explicitly (a length-neutral score, a floor per unit) or the brief author catches it before
+  the worker builds around it. AX2-4612S's brief scored "the fr16 order-5 model's total log-probability of the
+  whole decoded stream": a sum over a variable-length stream that rewards deleting any code to NULL, since every
+  character's own log-probability is negative. The worker's own control caught it (100/110 false deletions on a
+  null test) before any target ran, but only after the tool was already built -- a brief-time check is one
+  sentence and finds the same flaw before a $5 tool-and-control cycle has to find it instead.
```
