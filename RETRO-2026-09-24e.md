## Proposal 1: `.claude/briefs/check-solved.md` -- two additions, both from over-calls this window

## Proposal 2: `tools/ledger_check.py` (new, spec only) -- a script gate for the two problems the wording-only fixes didn't stop

Both LEDGER.md hygiene problems above (duplicate session ids, non-standard outcome codes) already have a fix on
file -- "grep before you append" (applied at RETRO-2026-09-24b, row 194) and "use only these five codes" (applied
at RETRO-2026-09-24d, row 396) -- and both fixes are text a worker reads once and then doesn't re-check against its
own row before pushing. This window shows both failing again, at a higher rate than before (outcome-code drift
64% here vs 32% in RETRO-2026-09-24d's window; a second exact-duplicate session id despite the Session column
being added for exactly this check). Per CLAUDE.md's own Usage item 2 ("scripts read, models judge"), this belongs
in a script the worker runs before pushing, not a third wording pass.

```
tools/ledger_check.py [--fix-suggest]
Reads LEDGER.md. For every data row: (1) extract the Session column; flag any session id that appears on more than
one row, printing both row numbers and their Outcome/cost so a human can pick which to keep; (2) extract the
Outcome column's leading token; flag any row whose token is not exactly one of D, D-, F, X, N (case-sensitive,
no trailing punctuation). Exit 0 if nothing flagged, exit 1 and print every flagged row otherwise (so it can gate
`tools/room.py --push LEDGER.md`, the way tools/decode_key.py already gates a stale reading). --fix-suggest prints,
for each non-standard code, the nearest documented code by the row's own language (e.g. a Lesson column starting
"Ran Nx its cap" suggests D-) without editing the file.
```

**Diff to `LEDGER.md`'s header**, requiring the check rather than restating the rule a third time:

```diff
--- a/LEDGER.md
+++ b/LEDGER.md
@@
 Before appending a row, grep LEDGER.md for the worker's session id (recorded in the ROOM.md claim line for that
 worker); if a row already cites it, do not append a second one -- a row a lane orchestrator did not itself
 write may already be there from another lane or the parent (RETRO-2026-09-24b: two exact-duplicate rows this
 window, from two of five concurrent orchestrators archiving the same session). Add a `Session` column after
 `Model` from 24 Sept 2026(b) rows carrying the session id, so this check is a grep, not a full-row string match.
+RETRO-2026-09-24e: the grep-first instruction and the five-code-only instruction below were both restated in this
+header once already (RETRO-24b, RETRO-24d) and both kept failing at a higher rate in the very next window (a
+second exact-duplicate session id; 64% of rows using a non-standard code, up from 32%). Run `python3
+tools/ledger_check.py` before every `tools/room.py --push` that touches LEDGER.md; a worker whose own row it flags
+fixes that row before pushing, not after.
```

Motivating rows: 194, 396, 422, 426, 449, 473, plus the outcome-code count in Standard Measures above.

## Proposal 3: CLAUDE.md `## Git` -- route GitHub pull-request/issue writes through a fresh worker

Row 454: "Close checked second-opinion pull requests 1-8 (parent's GitHub token stale)... Lesson: a long-lived
parent's GitHub MCP token expires; route pull-request and issue writes through a fresh Sonnet worker." This
happened mid-window, inside the nine-second-opinion sequence (rows 444-453, 465): the parent orchestrator that had
been running since early in the day could read the SECOND-OPINIONS-QUEUE.tsv rows and the PRs' content, but its own
GitHub MCP session couldn't close them, silently, until a fresh $0.24 Sonnet worker was spun up to do the actual
close. The lesson is recorded in the ledger but not written into any brief or CLAUDE.md, so the next long-running
orchestrator will rediscover it the same way.

```diff
--- a/CLAUDE.md
+++ b/CLAUDE.md
@@
 ## Git

 Commit directly to `main`. No pull requests unless asked. Stage by explicit path when several sessions share
 the repo. Never rewrite history.
+A long-lived orchestrator's GitHub MCP token can go stale mid-session without an error the orchestrator notices
+(confirmed 24 Sept 2026: closing eight second-opinion pull requests failed silently against the parent's token
+after several hours; a fresh $0.24 Sonnet worker closed them on the first try). Route any GitHub pull-request or
+issue write through a short-lived worker rather than a parent that has been running for hours, whether the write
+is a second-opinion PR close or an outreach issue post.
 One sanctioned exception, decided by the owner on 23 Sept 2026 after the repository went public: a single rewrite
```

Motivating rows: 444-454, 465.

## Proposal 4: CLAUDE.md -- a brief that says "not in this repository" must say where, and forbid the push outright

Rows 427-428: the grants scout ($4.40, Sonnet) and the grants applications worker ($4.90, Opus) were both briefed
that grants/correspondence material stays out of the public repository -- the table and drafts belonged in a
private artifact, per `outreach/private-repo.md` -- and both pushed public files anyway (`grants/`, six

also say where to write, and the worker must not push at all." That sentence is the fix; it just isn't anywhere a
worker reads before pushing. This is the same shape as proposals 2 and 3: a lesson learned once, recorded in the
ledger, never promoted into a document a future worker's brief actually points at.

```diff
--- a/CLAUDE.md
+++ b/CLAUDE.md
@@
 9. **Personal data stays out of the repo.** It is public. Log archive requests by date and archive, never with
    the sender's name, address or payment details.
+9a. **A brief that says material stays out of this repository must name the destination, and the worker must not
+   push here at all** -- not even as a placeholder "to be removed later." If the named destination (a private
+   repository, an artifact) does not exist yet, the worker stops and says so; it does not commit the material to
+   this repository in the meantime. Lesson of 24 Sept 2026: two workers (grants scout, grants applications),
+   briefed only that the material "stays out of this repository," both pushed it here anyway; both fixes now sit
+   in this repository's history pending the owner's purge (`tools/purge_history.sh`).
```
