## 4. The STATUS.md heading guard (landed this window) protects against a rebase picking the wrong side, not
   against the failure that actually happened -- a session's own in-place edit dropping a heading before it ever
   commits

Two STATUS.md section-drop incidents this window: commit 9a1e34b (19:50, predates this window, motivated retro l's
own proposal 2) and commit a34cd00 (22:12, LANE ZX2 orchestrator, this window), which dropped the LANE B3 and
LANE B4 handoff sections. `tools/room.py`'s `headings_ok()` (built 22:20-22:24 by RETRO-APPLY-LEARN2, in direct
response to the *first* incident) landed a few minutes after a34cd00, so on paper it should have caught a repeat --
but it could not have caught a34cd00 specifically, and would not catch a repeat of the same shape today. LANE ZX2's
own ROOM.md line names the actual cause: "my section rewrite ran to the B2 heading and swallowed B3/B4 between" --
a plain in-place text edit inside the session's own working copy, before any commit, not a merge conflict resolved
the wrong way. `push()`'s `watched` snapshot is taken *after* `git commit`, from the local working tree -- i.e.
from the file exactly as the session's own edit already left it. If that edit already deleted a heading, the
snapshot never contained it, so `headings_ok()`'s `before - after` comparison across the rebase has nothing to
detect: both sides of the comparison agree the heading is gone. The guard is real and correctly designed for the
failure mode it was built for (RETRO-2026-09-25l proposal 2's "rebase keeping the wrong side of a conflict"); it is
not sufficient for the failure mode that actually recurred, and the new test (`test_room_headings.py`) only
exercises the rebase-drop shape, not a pre-commit local edit, so it would not have caught this either.

The fix is the comparison retro l's own original diff proposed and the landed version did not quite implement:
compare against `origin/main`'s heading set fetched fresh, not against the local working tree's post-edit state.

```diff
--- a/tools/room.py
+++ b/tools/room.py
@@ def push(message, paths):
     if paths:

     if not sh("git", "diff", "--cached", "--quiet").returncode:

+    # Snapshot origin's own headings BEFORE this commit is created (25-26 Sept 2026, RETRO-2026-09-26a):
+    # a34cd00 (22:12, LANE ZX2) dropped two STATUS.md sections in the session's own local edit, before any
+    # commit or rebase -- headings_ok()'s post-commit, pre-rebase snapshot already reflected the drop, so it
+    # could not flag it. Comparing against origin/main directly catches a self-inflicted drop the same way it
+    # catches a rebase mis-merge.
+    sh("git", "fetch", "-q", "origin", "main")
+    origin_watched = {p: headings_from_ref("origin/main", os.path.relpath(p, ROOT))

+    watched = origin_watched

```

`headings_from_ref(ref, relpath)` is `headings()`'s existing regex applied to `git show ref:relpath`'s stdout
(`None` on a missing path, mirroring `headings()`'s own contract) -- one new small function, no change to
`headings_ok()` itself. New test case for `test_room_headings.py`: a "before" snapshot built from a *separate*
pristine copy of BEFORE (standing in for origin/main) while the local working file is written directly as
AFTER_DROPPED with no intervening rebase step, confirming `headings_ok()` still flags the drop when the local
edit, not a merge, is what removed the heading.
