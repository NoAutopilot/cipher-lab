## 1. A caution before the numbers below: the effort-split tool's headline number is not trustworthy yet

`tools/ledger_check.py --split 1227` reported: **S 0%, A 0%, V 4.7% (2 rows, USD 11.23), C 95.3% (38 rows, USD
227.46)**. Read literally this says the whole window was coordination and nothing else — no solving, no
acquisition. That is not what happened (the window's own rows describe intake, transcription, calibration and
control work throughout), and the number should not be repeated to the person as if it were.

The cause: `tools/data/effort_roles.tsv`'s second pattern, `\bparent\b -> C`, is checked before every task-specific
pattern (transcribe, intake, fetch, calibrate, control...) and matches on *any* row whose Role cell contains the
word "parent" — which is nearly every ordinary worker row in this ledger, because this repository's own naming
convention titles them "parent worker MONT-DOTS: ...", "parent worker INTAKE-4715-F61: ...", "parent worker
LAU-F58B: ..." (a worker *spawned by* the parent), not just an actual parent/orchestrator self-summary row like
"parent 7m (Orchestrator 14): ...". The pattern's comment says it exists to catch the latter; it also silently
eats the former. Rebuilding the split without that shortcut (a quick one-off check for this retrospective, not a
committed fix) leaves 31 of 58 rows matching *no* pattern at all, because this repository's actual code names
(MONT-RECROP, F61-CAL, PR-LAND-20, CAMPAIGN-SEED-*, WAIT-PASS-A) don't carry the generic verbs the table checks
for either — so today's table has nothing useful to say about most rows once the `\bparent\b` collision is removed.
This is proposal 1 below. Until it lands, treat any `--split` percentage as unverified and read the actual rows.

  found malsburg-hessen-1636's NEAR row 7 hours stale (Evidence cell newer than the Last-touched column) and had
  `tools/near_check.py` gain check (e) to catch exactly this. This window, matignon-mayenne-1586's NEAR row shows
  the same shape: its Evidence cell was extended in place with a full paragraph headed "MAT-CCE (27 Sept 2026,
  parent worker): ..." (control-backed non-test, numbers in HYPOTHESES.md and NOTES.md), but the row's own "Last
  touched" column still reads "26 Sept 2026 23:50" — a full calendar day earlier — and `near_check.py`, run just
  now, does **not** flag it (only blitz-ciphers, koehler-1944 and mccormick-1999 are flagged, all for the ordinary

  and the row is silently skipped rather than flagged. The fix built for malsburg does not catch matignon because
  the two rows happen to write dates in different granularities. Proposal 3 below closes that gap.

## 6. Proposed changes (five; applied by nobody in this run)

**P1. `tools/data/effort_roles.tsv`: stop `\bparent\b` from matching "parent worker" rows.**
Motivating rows: essentially all 42 of this window's classified rows (`tools/ledger_check.py --split 1227`
output, section 1 above) — e.g. line "parent worker INTAKE-4715-F61: ..." (intake+transcription, bucketed C),
"parent worker MONT-DOTS: ..." (transcription attempt, bucketed C).
```diff
-orchestrator	C
-\bparent\b	C
+orchestrator	C
+^\s*parent\s+(\d+|[A-Za-z0-9]+\s*\(Orchestrator)	C
```
Add a short comment above the changed line explaining the distinction (a parent's own self-ledger row starts
"parent 7m (Orchestrator 14): ..." or "parent <number>:"; an ordinary worker's role starts "parent worker
<NAME>: ..." and must fall through to the task-specific patterns below). Because removing the shortcut leaves
most rows unmatched (section 1), also add this repository's own recurring code-name families so the table has
something to match: `\bPR-LAND\b -> C`, `\bCAMPAIGN-SEED\b -> A`, `\bWAIT-(CHECK|PASS)\b -> C`, and a fallback
line noting that a row matching nothing stays in the existing "classify by hand" list rather than defaulting
anywhere. Re-run `--split` after the fix before trusting the number in the next retrospective.

**P2. `tools/next_steps.py --wait-only`: skip a target with a live claim or an active campaign.**
Motivating row: spinelli-beinecke-c1515, section 5 above.
```diff
+    # Before listing a target as wait-only, check for a live ROOM.md claim or a CAMPAIGN.md
+    # file whose most recent step is younger than, say, 12 hours; skip it (or label it
+    # "wait-only (stale: live worker attached)") rather than reporting it as idle.
```
Concretely: read `ciphers/<target>/CAMPAIGN.md`'s newest step timestamp (already written by every campaign
runner step, per the ROOM.md log format) and the target's most recent ROOM.md claim; a target with either newer
than the tool's own staleness window is excluded from `--wait-only`'s output, or annotated rather than listed
bare.

**P3. `tools/near_check.py`: `DATE_RE` gets a date-only fallback.**
Motivating row: matignon-mayenne-1586, section 3 above (the MAT-CCE paragraph's "(27 Sept 2026, parent worker)"
heading carries no clock time and is invisible to check (e)).
```diff
 DATE_RE = re.compile(r'(\d{1,2})\s+([A-Za-z]+)\.?\s*(\d{4})?[, ]+(\d{1,2}):(\d{2})')
+DATE_ONLY_RE = re.compile(r'\((\d{1,2})\s+([A-Za-z]+)\.?\s*(\d{4})?,')
```
`find_evidence_drift` tries `DATE_RE` first as today, then falls back to `DATE_ONLY_RE` for a parenthesised
"(DD Mon YYYY, ..." heading (the shape every dated sub-entry in this repo's NEAR.md and NOTES.md cells already
uses), treating a date-only match as 23:59 of that day for the "postdates Last touched" comparison (the
conservative direction: a date-only mention should trigger the warning at least as often as a timed one, not
less).

**P4. CLAUDE.md Usage item 6: land the vision-call/per-sheet pricing rule where every brief already has to read
it, instead of a "README common tail" that isn't one file.**
Motivating rows: INTAKE-4715-F61 (1.51x), INTAKE-SPINELLI (1.48x, "despite the stop-short instruction"),
LAU-F58B (2.18x, self-diagnosed as the same GOLD-4D-class mispricing) — section 3 above; RETRO-2026-09-27x P1,
whose proposed text never landed in CLAUDE.md itself (checked: no "vision call" text anywhere in the file).
```diff
 6. **Fan-out limits.** At most four subagents at once per worker; two transcription passes, not three, unless
    the two disagree on more than a tenth of the rows.
+   **Vision and per-sheet calls are a counted, priced unit (28 Sept 2026, this retrospective, after
+   RETRO-2026-09-27x P1 went unlanded and repeated three more times: INTAKE-4715-F61, INTAKE-SPINELLI,
+   LAU-F58B).** A brief that sends any image, crop or sheet to a model states "at most N vision/sheet calls"
+   and prices the cap as N x the per-call rate (about USD 1.5-2 a call on native crops), not as one call per
+   *pass* regardless of how many sheets that pass actually reads. Before pricing, count the sheets a leaf's own
+   cut will produce (a 60-line leaf cut one row per band is tens of sheets, not one) and multiply.
```

**P5. Batch second-opinion PR landings instead of one worker per arrival.**
Motivating rows: 11 separate `PR-LAND-13` through `PR-LAND-24` workers this window, USD 1.70-5.94 each, about
