## 4. Proposed changes (five; applied by nobody in this run — see section 2 for why that is expected this time)

Motivating evidence: section 2 — RETRO-2026-11-09 P1 sat unapplied for a structural reason, not a priority
one: the only session with the standing habit of applying retro fixes is the one that is down.
```diff
+**Cross-account apply (16 Nov 2026, RETRO-2026-11-16 P1).** When the account that normally applies a
+retrospective's proposals has had its parent silent past 24 hours (per the existing stall rule), any other
+live orchestrator session (another account's parent, or the owner-account orchestrator itself) may spawn a
+short-lived worker to apply a proposal that touches only briefs, tools or workflows -- the same gate
+CLAUDE.md's Improvement loop already uses, just not restricted to one account's session being the one to
+pull the trigger.
```

```diff
+176.
```

Motivating evidence: section 3 — parent (3 Nov) and dispatcher (11 Nov), eight days apart, same symptom.
